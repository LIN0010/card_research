# Card Research：第一階段 UI／UX 重構

## 審查範圍

網站名稱改為 Card Research。以奶白紙張底色、淡紫左卡匣、淡藍右卡匣、圓角與柔和陰影呈現收藏手帳風格。

僅重構前端紀錄頁與共用樣式；店家與機台管理、歷史搜尋／匯出保留原操作流程，登入／註冊／重設密碼的邏輯不變。沒有修改 Supabase schema、RLS、RPC、資料載入、冪等重試、原始序號或稽核資料。既有抽卡資料仍沿用原 ID。

## 出卡紀錄頁

1. **目前抽卡狀態**：店家、機台、版本、目前局數、有效紀錄張數與場次名稱。切換機台／既有場次收在「切換」面板；「開始抽卡」開啟新場次視窗。
2. **快速出卡紀錄**：左右兩個大型選擇鈕，來源不明是輔助選項。初始及每次儲存成功後均不選來源，避免沿用上一張；儲存失敗保留原卡號、來源、稀有度。
3. **卡號快捷**：可由版本代碼或自訂前綴點選帶入，沒有自動改寫。完整卡號、零、P 字尾及原始空白保留。稀有度直接點選，P 字尾提示仍可手動覆寫。
4. **本次卡序**：預設左右雙欄，另有整體時間順序與不明來源檢視。每張卡片只顯示有效順序、卡號與稀有度；「更多操作」內可修改、撤銷或展開詳細資料與操作紀錄。
5. **場次操作**：本次卡序底部提供撤銷上一筆、下一局（卡序延續）、結束本次紀錄。兩個主要操作下方各有使用時機說明；結束前需確認，取消不會寫入。已撤銷資料仍可展開查看；原始序號不重排。
6. **進階設定**：卡匣批次、不確定狀態與更換入口收在可展開區域。

手機底部導覽為「出卡紀錄／店家與機台／歷史紀錄」；桌面導覽位於頁首下方。手機雙欄卡片編輯時會暫時改為單欄，保留足夠輸入空間。

## 名稱與資料對應

前端「抽卡場次」仍對應原 `observation_segments`，「下一局」仍使用原 games 與 start_game RPC。換局不重設順序；不同機台與場次不串接。有效顯示編號與原始側序的區別保留在詳細資料。

此分支**不需要執行新的 SQL migration**。

## 驗證方式

```bash
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

E2E 以正式編譯的測試輸出、Chromium 及 PGlite 執行既有流程與 UI 回歸，並檢查 320、360、390、768、1440px 寬度。手機／桌面檢查截圖保存在忽略的 test-results 目錄，僅供本機視覺驗證。測試使用模擬 Auth／HTTP 傳輸，不表示已驗證託管 Supabase 或已部署網站。
